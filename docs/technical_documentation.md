# Technical documentation

This document is a developer-oriented map of the current implementation. The short entry points are README.md, docs/SYSTEM_DESIGN.md and docs/PRACTICE_DESIGN.md. The chronological development record is preserved separately in docs/upsc_polity_capstone_development_log.txt.

## Start here

    .venv/bin/python -m streamlit run app.py
    .venv/bin/python -m pytest
    .venv/bin/python docs/diagrams/render_diagrams.py

Set OPENAI_API_KEY in a local .env file for new generation. The offline test and benchmark-check commands do not need an API key.

## Source preparation

src/ingestion/extract_text.py extracts PDF pages. prepare_documents.py retains source and document metadata. chunk_documents.py uses a 1,000-character chunk and 150-character overlap. save_chunks_jsonl.py writes data/processed/chunks.jsonl. The current source snapshot contains Constitution and selected NCERT text only.

## Runtime modules

app.py configures Streamlit and routes Practice, My Practice and How it works. src/practice/service.py validates requests, reuses eligible SQLite records, streams the generation graph and saves a run report. src/practice/models.py defines the request, question and five-gate publication contract. src/practice/store.py owns the questions and runs tables.

src/orchestration/graph.py defines the fixed LangGraph edges. src/orchestration/nodes.py retrieves source packets, calls the candidate generator, extracts claims, verifies facts or options, audits quality, writes reviewed notes and decides ACCEPT, REVISE or REJECT. Generation evidence is not silently reused as verification evidence.

src/retrieval contains semantic and experimental retrievers. The current path uses semantic embeddings, NumPy similarity and a cross-encoder. BM25, hybrid and parent-child implementations are retained as experiments and reports, not active practice retrievers.

src/verification contains parsers, claim construction, page and Article context, source quotation binding, fact verification, direct option verification, quality auditing and learning-note review. The lexical absence checker is a scoped special case for explicitly quoted terms.

## State and persistence

The LangGraph state holds the current candidate, evidence packets, claims, verdicts, audit results, notes, failure reasons and retry count. A revision clears prior checks. Accepted records include a content-derived ID, corpus hash, generation-policy version and reviewed evidence. Learner answers remain in server memory.

## Evaluation

src/evaluation/evaluate_benchmark.py runs the frozen 75-question diagnostic with answer keys withheld until grading. evaluate_retrieval.py measures annotated page hits without an LLM. run_all.py checks report dependencies and retrieval-depth metadata. Historical generation, judge and stability artifacts remain in data/evaluation and are labelled by their original protocol.

![Evaluation flow](diagrams/evaluation_flow.png)

Run:

    .venv/bin/python -m src.evaluation.evaluate_benchmark --check
    .venv/bin/python -m src.evaluation.run_all --check

## Error and cost boundaries

The OpenAI client uses a 45-second timeout and one SDK retry. Each requested slot allows one initial candidate and at most two revisions. Explanation writing has one local repair. Errors are saved by class; credentials and prompt bodies are not logged. src/practice/costs.py estimates standard-tier text cost from recorded tokens and reports incomplete usage instead of assuming zero.
